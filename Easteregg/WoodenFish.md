> “Tap once, merit +1. Tap ten thousand times, the bug leaves on its own.”

## 一、缘起

我有一个习惯：每次回看自己的代码、被自己打脸、被用户指出问题之后，敲一下木鱼。

一开始只是我一个人在敲。
后来还是我一个人。
再后来，我开会的时候，屏幕上也会放着一个 HTML 木鱼，一边讨论一边敲。

不是迷信。是安抚情绪。

自我 Code Review 是被打脸最多的场合。
你说得对，你也说得对，但你们两个说的不是同一件事。
这时候，敲一下木鱼，功德 +1。

你没有赢。但你没有炸。这就是功德。

## 二、木鱼本体

FluentGit 的电子木鱼是一份**独立 HTML 文件**，放在：

```
Easteregg/WoodenFish.html
```

双击打开即可。无需构建，无需联网，无需依赖任何 CDN。

它只有一个功能：
**点一下，功德 +1。**

### 木鱼外观（ASCII 版）

```text
        ___..___
     .-'        '-.
    /   _      _   \
   |   (_)    (_)   |
    \      __      /

```

### 木鱼规格

| 项目 | 规格 |
|---|---|
| 载体 | 单文件 HTML |

| 音效 | Web Audio API 合成，无外部音频文件 |

| 兼容 | 任何现代浏览器，含 Edge / Chrome / Firefox / Safari |

## 三、敲击代码

如果你想把木鱼内嵌到 FluentGit 主界面里（我们不建议，但你可以），
以下是 `WoodenFishService` 的最小实现：

```csharp
using System;

namespace FluentGit.Services;

/// <summary>
/// 电子木鱼服务。
/// 只做一件事：把 merit 加一。
/// 不加锁，不持久化，不上传。
/// </summary>
public static class WoodenFishService
{
    private static long _merit = 0;

    public static long Merit => _merit;

    public static event Action<long>? OnKnock;

    public static void Knock()
    {
        _merit++;
        OnKnock?.Invoke(_merit);

        // 功德到一定数量时，打一句提醒
        if (_merit % 108 == 0)
        {
            System.Diagnostics.Debug.WriteLine(
                $"[WoodenFish] 功德 {_merit}。去喝杯水吧。");
        }
    }

    public static void Reset()
    {
        // 通常不需要。功德不可清零。
        // 但如果你非要清，请负起责任。
        _merit = 0;
    }
}
```

调用示例：

```csharp
WoodenFishService.OnKnock += (n) =>
{
    // 更新 UI
    MeritTextBlock.Text = n.ToString();
};

WoodenFishService.Knock();
```

### 关于 108

**108** 是佛教传统中一个常用的数字。
在这里，它只是一个**随机出现的温柔提醒**：

> 你在敲木鱼，你已经敲了 108 下了。
> 但这 108 下里，你一次都没有看代码。
> 去看代码。

## 四、敲击规程

### 4.1 何时敲

| 时机 | 敲多少 |
|---|---|
| Code Review 被指出了一个真 Bug | 3 下 |
| Code Review 被指出了一个假 Bug | 1 下（但心里敲 100 下） |
| 需求又改了 | 6 下 |
| 别人在你面前用 `git reset --hard` | 9 下 |
| 你看到一段没有注释的 `#region` | 1 下 |
| 你看到有人把 `async void` 用在事件处理器以外的地方 | 3 下 |
| 你自己写了 `// TODO` 又过了三个月没改 | 21 下 |
| 你想 `git push --force` | 108 下。真的，先敲完再决定 |

### 4.2 何时不敲

- 在真机上调试崩溃的时候——**先看日志**。
- 在写代码的**思路正顺的时候**——**别打断**。
- 在别人正在给你讲一个技术问题的时候——**听人说完**。

木鱼是安抚工具，不是回避工具。

### 4.3 敲完做什么

敲完之后，什么都不要做。

**真的什么都不要做。**

不要立刻切窗口，不要立刻打开 IDE，不要立刻回消息。
就 5 秒钟，闭眼，呼吸。

然后回去，继续干活。

## 五、禁忌条款

### 第一诫 · 不可连点

不得以每秒 10 下的频率点击木鱼。
这不是功德，这是刷量。刷量不产生功德，只产生误触。

### 第二诫 · 不可自动化

不得写一个 AutoHotkey 脚本自动敲木鱼。

**功德不能代打。**

你写了脚本，就是你偷懒。
你偷懒了，木鱼就白敲了。

### 第三诫 · 不可统计排行

不得在团队里做“功德排行榜”。

这会把一件好事，变成一场内卷。
**内卷的尽头，是一堆人半夜三点在敲木鱼。**

### 第四诫 · 不可将功德用于交换

不得使用以下语句：

- “我都敲了 1000 下了，这个 PR 你能帮我 review 一下吗？”
- “我功德比你多，听我的。”
- “我功德不够，你来。”

功德不能议价。

### 第五诫 · 不可许愿

不得对着木鱼许愿，比如：

- “愿这次 build 通过。”
- “愿这个 Bug 能复现。”
- “愿产品经理今晚不要改需求。”

**这些都不归木鱼管。**
木鱼只管一件事：**你已经敲过了。**

### 第六诫 · 不可外传为信仰

不得在公开场合宣称：“FluentGit 团队相信电子木鱼。”

对外统一口径：

> “电子木鱼是团队内部的一个情绪调节小工具。”

就这样。

### 第七诫 · 不可声张功德

不得在 commit message 里写：

```
fix: 修了个 bug (功德 +100)
```

Git log 是留给历史的。木鱼是留给自己的。

## 七、常见问题

**Q1：敲木鱼真的能加功德吗？**
A：不能。功德是虚构的。
但敲完之后，你会**稍微平静一点**。这是真的。

**Q2：为什么是木鱼，不是佛珠、转经筒、香炉？**
A：因为木鱼有声音。
**有声音的东西，敲起来才有反馈。**
反馈让你觉得“我做了点什么”。这就是它存在的意义。

**Q3：我可以自己改 HTML 里的样式吗？**
A：可以。
但请不要改成赛博朋克霓虹风。
**木鱼不适合发光的。** 真的。

**Q4：我可以把功德数据上传到服务器吗？**
A：不可以。
**功德是私事。**

**Q5：我敲了木鱼之后，Bug 还没修好，怎么办？**
A：去看代码。
木鱼帮你冷静，但不帮你 debug。

**Q6：我可以把 `WoodenFish.html` 发给朋友吗？**
A：可以。
但请连带这份 `WoodenFish.md` 一起发。
否则他不知道自己被卷进了什么。

**Q7：这个 HTML 能离线用吗？**
A：能。
它是单文件，无外链，无 CDN。
**断网也能敲。**

**Q8：我能把敲木鱼的次数写到 `localStorage` 里吗？**
A：你可以。
但请不要。**刷新即清零，是无常的提醒。**
